# Replicating this analysis on a different dataset

This repository builds an empirically audited causal DAG for one dataset. The method is not specific
to NSW CTP claims — it applies to any tabular dataset generated by a process with a known chronology
or a known rulebook.

This guide is the general recipe. Worked examples throughout refer back to the CTP implementation in
[`causal/build_ctp_causal_dag.py`](../causal/build_ctp_causal_dag.py).

> **The reference implementation is not a model of step 4.** The CTP graph's edges were generated by
> a language model and never reviewed by a domain expert (see
> [`causal-algorithm.md`](causal-algorithm.md)). Its *machinery* — the band constraint, the build
> assertions, the audit, the m-graph, the claim verifier — is worth copying. Its *elicitation* is the
> step you should do properly and it did not. Where this guide says "interview someone who works the
> process", that is advice the CTP build skipped.

---

## 0. Decide whether this method fits your data

The method is **expert elicitation with a data audit** — where "expert" means a human who works the
process. It is the right choice when:

- ✅ **The generating process has a knowable order.** Insurance claims, clinical pathways, loan
  origination and servicing, manufacturing lines, regulatory processes, customer funnels. If you can
  draw a timeline, you can draw the bands.
- ✅ **Rules or statutes govern part of the outcome.** Thresholds, formulas, eligibility gates,
  tariffs. These give you edges whose direction is not open to argument.
- ✅ **n is small or missingness is heavy.** This is exactly where discovery algorithms are unstable
  and domain knowledge is worth most.
- ✅ **Someone will consume the graph** — a generative model, an adjustment set, a fairness audit,
  a review. A graph nobody uses is a diagram.

It is the wrong choice when:

- ❌ **Nobody knows the mechanism.** Genomics, unstructured embeddings, exploratory sensor data. Use
  discovery, and be honest about the equivalence class.
- ❌ **You want the graph to tell you something you do not already believe.** Elicitation cannot do
  that. It formalises and stress-tests what you believe; the audit tells you where you are wrong.
- ❌ **You have no domain access.** Do not elicit a graph from a data dictionary alone. Interview
  someone who works the process.

A useful middle path: elicit the graph, run a discovery algorithm as well, and score the
disagreements. Where they agree you have corroboration; where they disagree you have a question
worth asking someone.

---

## 1. Profile the data before drawing anything

You cannot elicit sensibly without knowing what is in the table. Produce, for every column: dtype,
missing fraction, distinct count, min/max, and — for the target — the skew on both raw and log
scales. The CTP project keeps this as a committed `*.meta.json`
([`ctp/ctp.meta.json`](../ctp/ctp.meta.json)) so the profile is versioned alongside the data.

Three things to look for specifically, because each one changes the design:

- **Missingness structure.** Not just rates: cross-tabulate blank rates against other columns. If
  blank-in-A differs by level of B, you have an informative-missingness edge to model (§7). Count
  distinct missingness patterns and the complete-case fraction — CTP is 27.6% complete across 25
  patterns, which rules out complete-case analysis on its own.
- **Deterministic or near-deterministic relations.** In CTP, `NEL + FEL ≈ Lump Sum` (correlation
  0.94). These are arithmetic edges, not statistical ones, and they usually mean your target is a
  **collider** (§6).
- **Zero-inflation and gates.** 44.2% of recorded CTP non-economic-loss values are exactly $0,
  because of a statutory threshold. A gate is a causal fact, and it will break any model that treats
  the column as continuous.

---

## 2. Define the bands

**This is the highest-leverage step.** Bands are a coarse temporal or logical partition of the
variables, and they do most of the orientation work before you consider a single edge.

Write them as a chain, each with a one-line rationale:

```
fixed characteristics → the triggering event → the process that follows
    → what gets contested → intermediate outputs → the final outcome
```

Rules that make bands work:

1. **Every edge runs to the same band or a later one. Never backwards.** This is a hard constraint,
   enforced in code, and it is what turns a vague picture into a DAG.
2. **Aim for 4–7 bands.** Fewer and the constraint buys you nothing; more and you will be arguing
   about which band a variable is in rather than about mechanisms.
3. **Put roots in band 1** — the things nothing in your dataset can change.
4. **Put the target in the last band alone** if it is a pure sink, i.e. it causes nothing else in the
   table. Most outcome variables are.
5. **Be suspicious of variables that seem to fit two bands.** Usually the variable conflates two
   things and should be split — or, more often, it belongs in the *later* band and you were tempted
   by its correlation with something early.

The classic elicitation error this prevents: treating an *effect of severity* as a *cause of the
award*. In CTP, `Nature` (settlement approval vs damages assessment) correlates with a 2.6× median
award gap. It is very tempting to make it a cause. It is not — the contest is an effect of how
severe and contested the claim is, and the gap has to be reproduced through confounding. Band
placement forces that argument to happen explicitly.

---

## 3. Elicit the nodes

One node per modelling column, with `id` **exactly matching the column name** so the audit can join.
Give each one:

| Field | Why |
|---|---|
| band | The ordering constraint |
| kind (`numeric` / `ordinal` / `categorical`) | Downstream model choice |
| a prose note | What it measures, why it sits where it does, measurement caveats |

Write the notes honestly. The most valuable ones state a limitation: *"46.9% missing — recorded only
when it was assessed"*, *"near-constant here (91% at the top level)"*, *"the accident forces that
produced it are unobserved — treated as exogenous noise"*. A node whose note says nothing interesting
is a node you have not thought about.

---

## 4. Elicit the edges

For each candidate edge record **five** things: source, target, sign, prior strength, and a prose
mechanism.

### The mechanism is the deliverable

> **If you cannot write one sentence naming the pathway, the edge does not exist.**

This single rule does more for graph quality than any amount of tooling. "They're correlated" is not
a mechanism. "Degenerative change accumulates, so older claimants arrive with more prior pathology on
the record" is. The mechanism strings are what a reviewer reads and attacks; they are the audit
trail that makes the graph falsifiable rather than merely asserted.

### Sign and strength

- **`sign`** is the direction of the **direct** effect with the other parents held fixed — *not* the
  correlation you expect to see. These differ, often, and the difference is the interesting part.
- **`strength`** is your prior confidence in the *mechanism*, on a 3-point scale. Statutory
  arithmetic is `high`; a plausible-sounding behavioural story is `low`.

**Record both before you compute any correlations.** If you set the sign after seeing ρ you have
thrown away the audit, because the audit only means something if the assertion was made blind.

### Elicitation prompts that work

Go variable by variable and ask:

- What would have to change for this to change? (→ parents)
- What does this change downstream? (→ children)
- Is there a rule, formula or threshold that determines it? (→ high-strength edges)
- What sets it that we did not measure? (→ note it as exogenous, or as unobserved confounding)
- If two variables correlate, what third thing causes both? (→ the confounder, which is usually
  already a node)

### Leaves and sinks

Actively look for variables that *record* the process rather than *drive* it. In CTP,
`Legal Procedural Complexity` takes five parents and has no children. Making it a parent of the award
would confuse a correlate of severity for a cause of it — a mistake that would look fine in every
goodness-of-fit statistic.

## 5. Encode and validate

Put the bands, nodes and edges in a build script as module-level literals, and make the script fail
loudly on any structural violation. A skeleton, generalising
[`build_ctp_causal_dag.py`](../causal/build_ctp_causal_dag.py):

```python
"""Build the <domain> causal DAG.  Run: python causal/build_dag.py"""
from __future__ import annotations
import json
from pathlib import Path

import numpy as np
import pandas as pd
from scipy import stats

ROOT = Path(__file__).resolve().parent.parent
CSV = ROOT / "data" / "<dataset>.csv"
OUT = Path(__file__).resolve().parent / "<dataset>_causal_dag.json"

BANDS = [
    {"id": "b1", "label": "...", "blurb": "..."},
    # ... 4-7 bands, in chronological order
]

NODES = [
    dict(id="<exact CSV column>", short="...", band="b1", kind="numeric",
         x=118, y=130, note="What it is, why it sits here, what's wrong with it."),
    # ... one per modelling column
]

EDGES = [
    ("<source>", "<target>", "+", "high", "The mechanism, in a sentence."),
    # ... grouped by band transition
]

HEAVY_TAILED = {"<target>", "<other dollar/count columns>"}   # log1p before correlating
BINARISE = {"<string col>": "<level coded as 1>"}


def topological_order(nodes, edges):
    """Kahn's algorithm; ties broken by declaration order for stable output."""
    hint = {n["id"]: i for i, n in enumerate(nodes)}
    parents = {n["id"]: set() for n in nodes}
    for src, dst, *_ in edges:
        parents[dst].add(src)
    remaining = {k: set(v) for k, v in parents.items()}
    out = []
    while remaining:
        ready = sorted((k for k, v in remaining.items() if not v), key=lambda k: hint[k])
        if not ready:
            raise ValueError(f"cycle detected among {sorted(remaining)}")
        for k in ready:
            out.append(k)
            del remaining[k]
        for v in remaining.values():
            v.difference_update(ready)
    return out


def spearman(df, a, b, min_n=30):
    """Pairwise-complete Spearman; log1p on heavy-tailed columns."""
    s = df[[a, b]].dropna().copy()
    if len(s) < min_n:
        return None, len(s)
    for name in (a, b):
        if name in HEAVY_TAILED:
            s[name] = np.log1p(s[name])
    if s[a].nunique() < 2 or s[b].nunique() < 2:
        return None, len(s)
    return float(stats.spearmanr(s[a], s[b]).statistic), len(s)


def main():
    df = pd.read_csv(CSV)
    num = df.copy()
    for col, positive in BINARISE.items():
        num[col] = (num[col] == positive).astype(int)

    # --- GATE 1: acyclicity + band ordering ------------------------------
    order = topological_order(NODES, EDGES)
    rank = {n: i for i, n in enumerate(order)}
    for src, dst, *_ in EDGES:
        assert rank[src] < rank[dst], f"back-edge {src} -> {dst}"

    # --- GATE 2: every node id is a real column --------------------------
    missing_cols = [n["id"] for n in NODES if n["id"] not in df.columns]
    assert not missing_cols, f"nodes not in CSV: {missing_cols}"

    # --- audit ------------------------------------------------------------
    csv_rank = {c: i for i, c in enumerate(df.columns)}
    edges_out = []
    for src, dst, sign, strength, mech in EDGES:
        rho, n = spearman(num, src, dst)
        conflict = (rho is not None and abs(rho) > 0.03
                    and ((sign == "+" and rho < 0) or (sign == "-" and rho > 0)))
        edges_out.append(dict(source=src, target=dst, sign=sign, strength=strength,
                              mechanism=mech, rho=None if rho is None else round(rho, 3),
                              n=n, sign_conflicts_marginal=conflict,
                              csv_order_violation=csv_rank[dst] < csv_rank[src]))

    parents = {n["id"]: [] for n in NODES}
    for e in edges_out:
        parents[e["target"]].append(e["source"])

    doc = dict(name="<dataset>", version="1.0", target="<target>", n_rows=int(len(df)),
               bands=BANDS, nodes=NODES, edges=edges_out, parents=parents,
               topological_order=order, csv_column_order=list(df.columns),
               stats=dict(n_nodes=len(NODES), n_edges=len(EDGES),
                          n_sign_conflicts=sum(e["sign_conflicts_marginal"] for e in edges_out)))
    OUT.write_text(json.dumps(doc, indent=2), encoding="utf-8")
    print(f"wrote {OUT}: nodes={len(NODES)} edges={len(EDGES)}")


if __name__ == "__main__":
    main()
```

**The assertions are the test suite.** Keep them in the build path rather than in a separate test
file — a graph with a cycle should never reach disk.

## 6. Audit the graph against the data

Now, and only now, look at the correlations. Five checks, in order of how much they will teach you.

### 6.1 Per-edge association

Pairwise-complete **Spearman** ρ, with `n` recorded next to it. Rank correlation because heavy tails
and monotone-nonlinear relationships are the norm; `n` because with heavy missingness the effective
sample varies wildly between edges and a reader needs to see which coefficients are supported.

ρ is **descriptive**. It does not orient anything, and a strong ρ on an edge is corroboration at
best.

### 6.2 Sign conflicts — the most informative output

Flag every edge where the asserted direct effect and the observed marginal disagree
(|ρ| > 0.03 filters noise around zero). For each one you must be able to **name the confounder**.

CTP has 7 of 49. Example: `Causation Complexity → Future Economic Loss` is asserted negative
(apportionment carves out non-accident loss) but correlates **+0.20**, because contested causation
arises precisely in the severe, high-value claims. Severity is the confounder, and it is already in
the graph.

Interpretation rule:

- **Conflict + you can name the confounder** → the graph is doing its job. Keep it and document.
- **Conflict + you cannot** → your sign is probably wrong, or a confounder is missing from the graph.
- **No conflicts anywhere** → be suspicious. Either your data has no confounding (unlikely) or you
  set the signs after looking at the correlations.

### 6.3 Colliders, especially at the target

A node with two or more non-adjacent parents is a collider, and conditioning on it induces spurious
dependence between them. **Enumerate colliders in code, do not hand-list them.**

Measure the damage on the important ones:

```python
def resid(v, z):
    X = np.column_stack([np.ones(len(z)), z])
    return v - X @ np.linalg.lstsq(X, v, rcond=None)[0]

rho_marginal = stats.spearmanr(a, b).statistic
rho_given_c  = stats.spearmanr(resid(a, c), resid(b, c)).statistic
```

CTP: ρ(NEL, FEL) = **+0.513** marginally, **−0.459** given `Lump Sum`. A one-unit swing. If your
target is a sum, a total, a score, or any aggregate of other columns, expect this.

### 6.4 Column order vs topological order

Count edges whose target precedes their source in the file. This matters enormously if anything
downstream consumes columns sequentially — an autoregressive generator, a chained imputer, a
stepwise model.

CTP reverses **34 of 49**, because the file leads with the money columns. Near-reverse-topological
order is the worst case for sequential models, and it is the single most common way a tabular
generator silently learns the wrong factorisation.

### 6.5 Deterministic relations

Check any near-arithmetic relationship holds at the rate you expect (CTP: `NEL + FEL ≤ Lump Sum` in
95.4% of rows with both recorded, median ratio 0.79). Record the real violation rate. Downstream, a
generator producing 4–5% violations is *correct*; one producing 0% or 25% is not. Do not clamp —
measure.

## 7. Model missingness as causal structure

If any column is missing non-randomly, do not impute it away — **add it to the graph**. For each
partially observed variable `V`, define a binary indicator `R_V = 1` meaning "not recorded", with its
own parents (an *m-graph*).

Find the edges empirically, by cross-tabulating blank rates:

```python
for col in df.columns[df.isna().any()]:
    for other in df.columns:
        if other == col or df[other].nunique() > 12:
            continue
        rates = df.groupby(other, dropna=False)[col].apply(lambda s: s.isna().mean())
        if rates.max() - rates.min() > 0.05:      # a mechanism worth encoding
            print(f"{col} blank rate varies by {other}: {rates.round(3).to_dict()}")
```

Then write the mechanism, with the numbers in it, because the indicators are not columns and the
conditional rates are the only evidence these edges will ever have. CTP examples:

- `Claimant Gender → R_Income`: 47.7% blank for female claimants vs 37.2% male.
- `R_Income → R_FEL`: 50.4% of income-blank rows are also FEL-blank, vs 4.1% otherwise — a shared
  cause, encoded indicator-to-indicator.
- `WPI % → R_WPI`: **self-masking**. Whether it is recorded depends on its own value. This is a
  self-loop in value space; it cannot be handled by conditioning and must be declared as an
  assumption in your results, not absorbed silently.

Three practical consequences:

1. Put `R_V` **before** `V` in the augmented topological order.
2. When `R_V = 1`, emit `NaN` and exclude the row from downstream conditioning sets.
3. Watch for **context starvation**. Fitting a node on seven parents when two are 45% missing can
   collapse the complete-case context to nothing. Set a floor (CTP uses 60 rows), fall back to the
   largest parent subset that clears it, and **log which parents were dropped**.

## 8. Publish the graph so it can be attacked

The graph is an assertion. It is only credible if a domain expert can inspect it without reading
Python. Two artefacts do this:

- **A JSON single source of truth** — every consumer (dashboard, generator, adjustment-set query)
  reads the same file. Nothing re-derives.
- **A self-contained HTML dashboard** — template with a `__DAG_JSON__` placeholder, filled by a
  ~30-line build script. No CDN, no build toolchain, one file you can email.

Views worth having, all driven off the same payload:

| View | Answers |
|---|---|
| Banded map, edges coloured by sign, weighted by strength | "Is this how the process actually works?" |
| Adjacency matrix, toggled topological vs file order | "How badly does the file order violate the graph?" |
| Collider + sign-conflict cards | "Where will a naive model go wrong?" |
| Missingness sub-graph with conditional rates | "Why is this blank?" |

Show the reviewer the `mechanism` text on click. That is the sentence they will disagree with, and
disagreement is the point.

## 9. Test what happens when the graph is wrong

There is no ground truth. A method that only works given a perfect expert graph is not usable, so
sensitivity to being wrong is part of the deliverable.

- **Perturbed-graph arm.** Reverse *k* ∈ {2, 5, 10} randomly chosen edges, re-check acyclicity, rerun
  everything downstream, report how far results move. If reversing 5 of 49 edges destroys your
  result, say so.
- **Discovery comparison.** Run PC-stable (or similar) and score orientation accuracy against the
  elicited graph. Expect it to be weak with small n; report it anyway.
- **A real-vs-real noise floor.** Compute every downstream metric on two disjoint halves of the
  *real* data. That gap is the floor. Any "improvement" smaller than it is noise, and you need this
  number before you believe any comparison.
- **Ablate the graph.** Run the downstream task with the graph and without it. If the numbers are
  identical, the graph is documentation — which is a legitimate outcome, but report it as one.

## 10. Checklist

**Before elicitation**
- [ ] Column profile: dtype, missing fraction, distinct count, range, target skew
- [ ] Missingness patterns counted; complete-case fraction known
- [ ] Deterministic / near-arithmetic relations identified
- [ ] Gates, thresholds and zero-inflation identified
- [ ] A domain expert is available (not just a data dictionary)

**Elicitation**
- [ ] 4–7 bands defined, in chronological order, each with a rationale
- [ ] Every node assigned a band, a kind, and an honest note
- [ ] Every edge has a one-sentence mechanism
- [ ] Sign = direct effect (not expected correlation); strength = prior confidence
- [ ] Signs and strengths recorded **before** any correlation was computed
- [ ] Leaves identified — variables that record the process rather than drive it

**Validation (in the build, as assertions)**
- [ ] Topological sort succeeds — no cycles
- [ ] Every edge runs forward in band order
- [ ] Every node id matches a real column

**Audit**
- [ ] Per-edge Spearman ρ with `n`, on log1p for heavy-tailed columns
- [ ] Sign conflicts flagged; a confounder named for each
- [ ] Colliders enumerated in code; the damage measured at the target
- [ ] File order vs topological order compared and counted
- [ ] Deterministic-relation violation rates recorded

**Missingness**
- [ ] `R_V` indicator per non-randomly-missing column
- [ ] Indicator parents found by cross-tabulation, with the numbers in the mechanism text
- [ ] Self-masking identified and declared as an assumption
- [ ] Context-starvation floor set, with dropped parents logged

**Publication**
- [ ] JSON artefact is the single source of truth
- [ ] Dashboard is self-contained and shows the mechanism text
- [ ] Build is deterministic and re-runnable in one command
- [ ] Limitations documented: what the method does *not* claim

**Robustness**
- [ ] Perturbed-graph arm
- [ ] Discovery comparison, reported even when weak
- [ ] Real-vs-real noise floor computed first
- [ ] Graph-ablation arm
